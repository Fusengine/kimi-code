# 03.5-elicit - Expert Self-Review

Expert agent self-reviews and self-corrects before sniper validation.

---

## Purpose

After coding (03-execution), the expert applies elicitation techniques to catch issues before sniper validation.

---

## Modes

| Mode | Flag | Behavior |
|------|------|----------|
| **Auto** | `--auto` (default) | Auto-select techniques based on code type |
| **Manual** | `--manual` | Only when the owner asks for it — present 5 techniques, owner chooses |

There is no skip mode: eLicit runs on every APEX task (`/apex-quick` included, with one quick technique), before Verify and eXamine.

---

## Workflow

```text
┌─────────────────────────────────────────────────────────┐
│  ELICIT (6 steps)                                       │
│                                                         │
│  Step 0: Init         → Load context                   │
│  Step 1: Analyze      → Detect code type               │
│  Step 2: Select       → Choose techniques (or auto)    │
│  Step 3: Apply        → Execute techniques             │
│  Step 4: Correct      → Fix own issues                 │
│  Step 4.5: Challenge  → ALWAYS challenger (fresh-ctx)   │
│  Step 5: Report       → Summary before sniper          │
└─────────────────────────────────────────────────────────┘
```

---

## Step 4.5 — Challenge round (MANDATORY, no exceptions)

ALWAYS run the `challenger` agent (or the `challenge` skill inline if a dedicated agent call is overkill) on the findings/fixes produced by Step 4, immediately after correcting and before reporting. This is systematic — every eLicit round triggers it, exactly like `sniper` runs at every eXamine. No judgment call on stakes: reaching this step is the trigger.

Feed the challenger fresh-context ONLY:
- **Claim**: "issues found and fixed" (the Step 3/4 findings + corrections)
- **Evidence**: the diff/findings produced
- NEVER the reasoning/investigation path that led to them (fresh-context is the whole point — see `challenge` skill principle 2)

Collect the verdict (`CONFIRMED` / `REFUTED` / `UNCERTAIN`) before proceeding to Step 5. A `REFUTED` verdict must be resolved (fix the finding) or explicitly owner-accepted before Step 5 reports "ready for sniper." An `UNCERTAIN` verdict is noted in the Step 5 report with what remains to verify.
